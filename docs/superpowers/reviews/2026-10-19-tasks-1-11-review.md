## Foundation findings: Tasks 1–3

These are additional to the detailed domain reports.

### B01 — Production readers are not committed, origin-safe projections

`src/storage/dashboard_data.py:824–872` reads any `structured_rules` row directly. A production-mode probe displays an uncommitted row explicitly marked `demo`. It has no canonical commit or accepted evidence.

`get_all_news_data` at `:875–979` drops the canonical origin `live` because it accepts only literal `production`. Conversely a loose JSON item labelled production is shown without a committed batch and receives fabricated `published_date='2024-01-01'`, `delta_value=0`, and a synthesized action with magnitude 1.0. This contradicts the unknown/null and canonical-read requirements even though no empty-store seeding occurs.

### B02 — The canonical publication boundary trusts invalid candidates

`src/storage/dual_layer_store.py:1545–1618` checks ownership/selected references but does not apply quality, source/origin, period, finite-value or series compatibility validation. Real temporary-store probes successfully commit/project:

- An accepted `BOGUS_UNSUPPORTED_RELATION` with no source document/evidence.
- A NaN observation whose period end precedes its start and whose series does not exist.
- A demo observation in a live batch.
- An EUR-per-tonne observation under an INDEX series definition.

Pure `validate_candidate` tests do not protect callers that never invoke it. This is an observable trust-boundary gap, including the real SMARD source adapter described in the source report. Rejections must occur at a responsible shared publication boundary; do not merely change the probes' expectations.

### B03 — Staged series metadata can supply committed endpoints

`SeriesDefinition` (`src/schemas/ingestion.py:286`) has no owning batch. Staging stores definitions globally; stage reference resolution at `dual_layer_store.py:1590` includes every canonical series regardless of the batch that introduced it. An uncommitted batch's series can therefore supply a `MEASURES` endpoint for another committed batch. Preserve metadata publication/availability consistency with facts and observations.

### B04 — The archive-object checksum is silently lost on canonical persistence

`BatchManifest.archive_sha256` exists (`src/schemas/ingestion.py:383`), but `BATCHES_SCHEMA` (`dual_layer_store.py:225–247`) omits it. After stage/commit and reopening, the canonical batch's hash is null. Ledger-based resume currently retains its separate copy and can work; do not misreport this as an independently reproduced resume failure. It breaks canonical round-trip/portable verification if only that representation is restored.

### B05 — Migration changes known source frequency

`scripts/ops/migrate_data.py:588–682` tests day-of-month heuristics before explicit DAILY and lacks an annual branch. DAILY `2024-01-15` becomes `[2024-01-01,2024-02-01)`, and ANNUAL `2024-01-01` becomes the same one-month interval. Explicit frequency must dominate heuristics. The present legacy records remain quarantined, which limits their current training impact; future verified migrations still need the fix.

### B06 — Source and review schemas do not fail closed on missing attestations

`src/config.py:176–242` defaults missing fee/subscription to zero/false. An enabled source with rights text but no access-fee/subscription declaration passes. `QualityDecision` (`src/schemas/ingestion.py:348`) accepts an arbitrary decision outside the four specified states. These are contract validation holes, distinct from already-known disabled source candidates.

## Highest-impact acceptance failures

1. **Potential data loss / unintended writes:** corrupt-remote cache eviction and restore traversal/overwrite. Repair before operational use or cleanup.
2. **Spending controls:** estimated reservations are settled as actual, uncapped output can exceed them, and each pilot source gets a fresh full budget. Zero-budget blocking is a positive check; it does not make a positive budget safe.
3. **Source truth:** the real official target and article/event paths do not flow into the same definitions/identities used by forecasting fixtures. Registry labels and adapter registration are not endpoint integration.
4. **Training truth:** labels bypass canonical commit/retraction/release selection. No honest historical eligibility/splits/calibration/frozen artifact flow is demonstrated.
5. **User-visible truth:** CPI relabeling, wrong horizon, fabricated calibrated forecast, resurrected rules and unrelated/uncommitted evidence. Disclaimers do not correct those computations.
